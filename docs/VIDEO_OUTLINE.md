# Video outline (~3 minutes)

> Video length and format rules are UNVERIFIED (waiver unread, checklist H1).
> This outline assumes a 3-minute screen recording with voiceover; adjust beats
> proportionally once the rules are known. Recording is the owner's action.

## Beat 1 — Problem (0:00–0:30, talking head or title cards)

"The agent said it was done. Was it?" Three pains in one sentence each:
approved intent evaporates, reviews skim, nobody can prove what the code
establishes. One line: "Build Brief keeps the evidence-backed link between
intent, implementation, correction, and understanding."

## Beat 2 — Capture to verdict (0:30–1:30, terminal)

- `bb capture` + `bb approve` (8s): "Drafts never verify; only the owner approves."
- `bb verify` output (20s): point at `[partial]`, `[not_established]`, and the
  `[critical]` auth orphan. "Missing proof is listed, not hidden. The orphan is
  a question, never an accusation."
- Freeze-frame the report's evidence lines (path + line range + revision).

## Beat 3 — Fix and re-verify (1:30–2:10, terminal)

- `bb fix` pack (5s): scope, do-not-touch, verify-after.
- Apply patch, commit, `bb recheck` (15s): expiry flips to `[supported]`,
  old findings invalidated. "The verdict changed only on fresh evidence."

## Beat 4 — Studio + workbench (2:10–2:45, terminal + browser)

- `bb quiz` + locate answer graded pass (10s).
- Workbench in browser (15s): intent page, run page, changes page with a
  disposition click. "Same ledger, no separate backend."

## Beat 5 — Honesty close (2:45–3:00, talking head)

"Benchmark: 22 dev, 6 holdout, all green on a seeded suite — a controlled
check, not a real-world claim. Two known gaps documented in the repo. Planned
work stays in the roadmap, out of the demo."

## Shot list

Terminal (large font, 100+ cols), workbench at localhost:3103, no faces
required. Do a full dry run from reset before recording (see DEMO_SCRIPT.md).
Keep the `.env` file out of frame; never show an API key.
